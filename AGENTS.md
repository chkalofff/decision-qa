# AGENTS.md — Decision-QA

Веб-приложение: backend на FastAPI (`backend/`), фронтенд — ванильные
ES-модули без сборки (`frontend/static/`), модельные серверы поднимаются
раннерами `server/run_*.sh`. Подробности — в `README.md`.

## Команды

- Тесты backend: `.venv-test/bin/python -m pytest -q` (из корня проекта)
- Тесты frontend: `/usr/local/bin/node frontend/tests/run.mjs`
  (node из /opt/homebrew на этой машине сломан — только /usr/local/bin/node)
- Запуск приложения: `nohup .venv-test/bin/python -m uvicorn backend.app:app --port 8000 > server/logs/app.log 2>&1 &`
- Live-smoke против реальных моделей: `RUN_LIVE=1 .venv-test/bin/python -m pytest -m live`

## Definition of Done для UI-изменений

После ЛЮБОГО изменения `frontend/static/**`, ДО отчёта пользователю:

1. `/usr/local/bin/node frontend/tests/run.mjs` — зелёный. Новая страница или
   статус без покрытия роняет contract-тесты — это сигнал дописать тесты, а
   не ослабить их.
2. `.venv-test/bin/python -m pytest -q` — зелёный (контрольный).
3. В финальном сообщении пользователю перечислить, что реально проверено,
   а не только что изменено.

Проверка глазами в браузере обязательна для любого визуального изменения:
DOM-тесты не видят вёрстку. Проверять минимум две ширины (~550px и ~1440px).

## Правила проекта

- Без git: все изменения additive, откат — удалением новых файлов/записей.
- API-ключи — только в `backend/credentials.json` (chmod 600), наружу через
  API не возвращать, не коммитить.
- Конфиг моделей — `backend/models_config.json`; правки из UI персистятся
  через `save_registry()`, ручные правки делать аккуратно (приложение
  перечитывает файл только при старте).
- Архитектура описана в `ARCHITECTURE.md`; при изменении архитектуры
  (новые модули, эндпоинты, статусы, потоки данных) `ARCHITECTURE.md`
  обновляется в том же изменении.
- Тесты исполняются локально и без сети; при изменении поведения тесты
  обновляются в той же работе, устаревшие — удаляются, а не отключаются.
