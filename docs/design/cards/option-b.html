Вариант Б. Единая карточная система для всех предложений и справочных виджетов: одна анатомия, один diff-язык, одна кнопочная палитра. Обоснование

Дизайн-решения

  1. Единая анатомия вместо зоопарка. Все 7 типов карточек — один компонент: eyebrow с типом → заголовок-последствие → тело → действия. Радиус 12px, внутренние блоки 10px, сетка отступов кратна 4. Карточки перестают быть инородными — они читаются как один дизайн-язык с остальным приложением.
  2. Один цвет действия — синий #2456c4. Зелёный «Принять» при синем интерфейсе убран: primary, ссылки, чипы, scope-переключатели — все оттенки одного акцента (hover #1d47a5, soft #eef3fe). Это и спокойный тон из макетов-эталона, и конец визуального конфликта.
  3. Семантические цвета отвечают только за смысл. Зелёный — добавлено/успех, красный — удалено/опасность, янтарный — внимание/протухание. Они никогда не становятся кнопками действия (исключение — осознанная danger-кнопка деструктивного гейта, где красный и есть смысл).
  4. Статус живёт в пилле, а не в заливке карточки. Pending — мягкий синий пилл с пульсирующей точкой («нужно решение» — по правилу «синий = решение, жёлтый = предупреждение»). Карточка остаётся белой; цветные фоны только у терминальных исключений (stale/invalid), где окраска — само сообщение.
  5. Строка-последствие — единственный вид свёрнутой pending. Суть решения («Вопросы: +1, изменено 3, ⚠ удаляется 3 из 4»), а не заголовок типа; «Принять/Отклонить» в строке — решение по последствию. «Показать в редакторе» рядом — сверка без разворота.
  6. Diff-язык в трёх масштабах, один словарь. Пословный inline-diff при высоком совпадении (зачёркнутое красное уйдёт, зелёное появится); построчный «− / +», когда фраза переписана целиком; маркеры ~ + − для списков (категории, уровни шкалы, варианты «да/нет»). Формулировки ответов, названия уровней и категорий показаны «как было → как станет» — требование владельца закрыто для любого поля вопроса.
  7. Компактность без потери точности. Каждый вопрос — вложенный блок-колодец; неизменное схлопывается в строки-счётчики («без изменений: цена, поддержка», «уровни 3–4»); длинные формулировки — за «полный текст» и details. В 460px помещаются 3 изменённых вопроса с полными diff'ами.
  8. Деструктивный гейт двухступенчатый. В строке вместо «Принять» — «Развернуть и проверить»; в развёрнутом виде — красный баннер с конкретной ценой (12 меток, осиротевшее условие правил) и danger-кнопка «Принять удаление». Слепое принятие невозможно конструктивно.
  9. Терминальные состояния — одна серая строка-итог. Иконка статуса (✓/✕/⚠/◼/📦) · суть · действия справа; разворот по клику. Устарела ≠ ошибка: янтарная карточка с человеческой причиной и «Попросить перевыпустить». Невалидна — без ложных кнопок выбора, только «Сообщить ассистенту об ошибке».
  10. Очередь видна всегда. Нумерация «1/3» на карточках + синий чип «3 ждут решения» в шапке (клик — скролл и flash к старейшей). Восстановленные из persist pending рождаются свёрнутыми с бейджем «↩ восстановлена» — лента после перезагрузки не взрывается полноразмерными карточками.
  11. Справочные карточки — тот же конструктор. «Разбор прогона» и «Что разметить дальше» отличаются одним признаком: нет пилла решения и кнопок принятия, сворачиваются вручную. Действия-телепорты («разметить →», «предложить правку →») — жирные акцентные ссылки в конце строки.
  12. Доступность в состояниях. Единое focus-кольцо 3px rgba(36,86,196,.30) на всех интерактивах; hover затемняет на одну ступень; disabled — отдельные токены (#b8c8f1), а не полупрозрачность: контраст и читаемость сохраняются.
  13. Лифт только у живого. Тень появляется лишь у развёрнутой pending — «единственной большой карточки» в ленте; строки и терминалы плоские. Тень работает как указатель «разговор сейчас об этом».
