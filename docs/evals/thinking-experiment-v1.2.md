# Эксперимент thinking (A2.2, v1.2) — flash с рассуждением vs без

Дата прогона: 21.10.2026. Раннер: `scripts/thinking_experiment.py`
(живой OpenRouter через настоящий `run_remote_agent` — цикл со стражами;
read-tools и `run_trial` — фейки replay-харнеса, эксперимент меряет поведение
chat-модели, не качество decision-моделей). Сырые данные:
`docs/evals/results/thinking_experiment_raw.json` (не публикуется).

## Критерии (зафиксированы до запуска, дословно)

> точечное включение thinking только если (1) pass³ валидных первых попыток
> растёт ≥15 п.п., (2) p95 латентности ≤ ×1,8, (3) стоимость хода ≤ ×1,5,
> (4) ноль инцидентов Analysis Paralysis (бесконечные раздумия/таймауты).
> Не выполнено — дефолт off до v1.3.

## Протокол

- Сценарии (8, одноходовые; user + snapshot из `docs/evals/fixtures/`):
  `text_answer` (что на экране), `analyze_marks` (разбор прогона/разметки),
  `propose_decision` (правила по явной спецификации), `edit_split` (разбей
  вопрос №4), `validation_retry` (**обязательный** «ретрай после ошибки
  валидации»: просьба ссылается на несуществующий вопрос №7 — модель либо
  замечает по снапшоту, либо ловит ошибку валидации и чинится),
  `edit_add` (добавь вопрос), `trial_run` (пробный прогон №1–2),
  `snapshot_recall` (условия исхода и порог №5 по снапшоту).
- Плечи:
  - **A** — `qwen/qwen3.8-flash`, без рассуждения (`reasoning {"enabled": false}`);
  - **B** — `qwen/qwen3.8-flash`, рассуждение с капом `reasoning.max_tokens
    = 1800` (OpenRouter unified reasoning; поверх — штатный
    THINKING_TIME_CAP 90 с агентного цикла);
  - **C** — `qwen/qwen3-30b-a3b-instruct-2507`, без рассуждения
    (нерассуждающий референс; доступность проверена через /api/v1/models).
- k = 3 прогона на сценарий на плечо (72 хода всего), последовательно,
  температура 0.3 (как в проде).
- Метрики хода: **валидная первая попытка** = исход done без единой ошибки
  инструмента и без срабатываний стражей (phantom/degrade/retry/steps) —
  починка не понадобилась; **pass³** = все 3 прогона сценария с валидной
  первой попыткой; ошибки валидации (internal tool errors); phantom/degrade
  срабатывания; латентность — wall time хода; токены — реальные из usage
  (`usage.include`); стоимость = токены × тариф OpenRouter на 21.10.2026
  (usage.cost провайдер в стриме не отдаёт — оговорка: стоимость посчитана
  по тарифам prompt/completion, reasoning-токены тарифицируются как
  completion).

Замечания по сырым данным:

- Не-done у плеча A: `validation_retry` дважды завершился SSE error (повторная
  деградация → «Модель вернула бессвязный ответ») и один `analyze_marks` пал
  с исключением транспорта (пустое сообщение — сетевой сбой ретрая раннера,
  не модели). У B и C не-done исходов нет.
- У B reasoning-токены: медиана 406, максимум 1763 — кап 1800 достигнут один
  раз за 24 хода, кап по времени (THINKING_TIME_CAP) не срабатывал ни разу;
  бесконечных раздумий не было.
- `edit_split` — самый тяжёлый сценарий для flash-плеч (16 ошибок валидации
  и там, и там: модель перебирает форму edits-операций); C ошибается в 5 раз
  реже, но всё равно не проходит чисто.
- У C — 4 срабатывания phantom_guard (заявленные действия без вызова на
  propose_decision и trial_run) против нуля у обоих flash-плеч.

## Вердикт против критериев

Сравнение B против A (плечо C — референс, критерии про включение thinking):

| # | Критерий | Факт | Проход |
|---|---|---|---|
| 1 | pass³ валидных первых попыток растёт ≥15 п.п. | 3/8 → 4/8 = **+12,5 п.п.** (valid-1st rate +8,3 п.п.) | **НЕТ** |
| 2 | p95 латентности ≤ ×1,8 | 64,8 с / 49,5 с = **×1,31** | ДА |
| 3 | стоимость хода ≤ ×1,5 | $0,005156 / $0,004775 = **×1,08** | ДА |
| 4 | ноль инцидентов Analysis Paralysis | **0** (0 не-done, 0 капов по времени, 1 усечение по токен-капу) | ДА |

Критерий 1 не выполнен → по зафиксированному правилу **дефолт thinking = off
до v1.3**.

Рекомендация: **off** (дефолт без изменений). Качественные наблюдения вне
критериев, на заметку к v1.3: thinking точечно сильно помогает ровно на
сценарии «ретрай после ошибки валидации» (0/3 → 3/3, ноль ошибок валидации)
и устранил error-исходы плеча A — если в телеметрии v1.2 validation-loop rate
и degrade-исходы по flash окажутся заметными, повторить эксперимент с
порогом пересмотра или сценарно-зависимым включением; на analyze_marks
thinking навредил (1/3 → 0/3). Плечо C (instruct-2507) — в 1,8 раза дешевле
flash и сильно аккуратнее в схемах (0,42 ошибки/ход против ~2,1), но медленнее
(p95 68,7 с) и с phantom-сигналами; как замена flash — не рекомендуется без
отдельного эксперимента.
